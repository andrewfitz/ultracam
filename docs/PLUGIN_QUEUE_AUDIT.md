# Plugin queue and ownership audit

Read-only source audit, 2026-10-27. Scope: Part A step 5 (A5) and Source Format B1c. No load test was run. Counts below are current implementation defaults, not format-independent memory guarantees. Source delivery preserves admitted frames under supported load; bounded downstream refusal must be counted separately from device loss. There is no arbitrary-load every-frame guarantee.

## Priority findings for typed controller adoption

1. **P0: source admission has no bound.** `CaptureController.receive` increments `queuedFrames` and dispatches a closure retaining `CapturedFrame` for every valid frame (`CaptureController.swift:981-1017`). `queuedFrames`, `maxQueuedFrames`, queue age and `lateFrames` observe backlog; they do not limit it. GPU admission waits for a three-slot semaphore in 50 ms slices, with a two-second failure (`LUTProcessor.swift:807`), so bounded GPU work does not bound the source dispatch queue. A slow-but-progressing GPU can indefinitely retain SDK-backed source buffers. Add atomic admission before retaining/enqueueing, with explicit downstream rejection counters and a byte/time budget; keep recording admission independent. Test: hold processing behind a semaphore, inject more than budget frames, assert bounded outstanding owners, exact refusals, prompt callback return, and eventual release after stop. Also test sustained progress just below source rate, which avoids the two-second no-progress timeout.

2. **P0: compatibility fan-out loses the explicit external owner.** `CapturedPixelBuffer` retains an optional SDK owner independently of its session (`DeviceAPI/CaptureDelivery.swift:5-14`), but `CaptureServicesBridge.swift:40` forwards only `buffer.value`. Controller, recorder and monitor can retain that CVPixelBuffer after the wrapper/owner dies. DeckLink's current SDK-backed buffer can own its native storage itself; that does not establish safety for another plugin using the explicit owner field. Typed adoption must carry the wrapper/lease through every asynchronous consumer and GPU completion, or establish an equivalent owner attachment on the actual pixel buffer. Test: publish a wrapper with a deinit probe owner, return from delivery and stop the session while processing/recording/monitor holds the frame; owner must live until the final consumer/GPU use ends. This is a contract-level lifetime gap, not a demonstrated DeckLink use-after-free.

3. **P1: source-only monitor delivery bypasses the output pool bound.** `offerSourceOnlyInOrder` dispatches a closure retaining `frame.image` for every selected frame (`CaptureController.swift:1164-1178`). A blocked delivery queue accumulates native buffers even though the monitor itself swaps latest slots. Bound admission before this hop or use a bounded ordered hand-off with explicit downstream-loss accounting. Test: block delivery, run monitor-only capture, inject over budget, assert retained owner count and rejection count. Do not silently change feed-camera cadence policy.

4. **P1: output pool bounds do not bound every delivery retention path.** GPU completion dispatches `DeliveryItem` plus output to delivery; delivery dispatches `DeliveryReport` back to capture (`CaptureController.swift:1123`, `1222`). Both structs can retain item source references. The 64-output threshold eventually refuses processing, but source ingress remains unlimited, and delayed reports can pin sources after output hand-off. Separate lightweight telemetry from frame owners and measure delivery backlog/bytes. Test with an injected slow preview/processed handler and independently blocked capture queue; prove each holding stage has a bound and reports overload.

5. **P1/B1c: packet/frame caps are unsafe as general plugin budgets.** Recording's 256 PCM packets fills in about 0.341 s at 96 kHz/128-frame callbacks, compared with roughly four seconds under DeckLink cadence. Twelve video frames cover 0.2 s at 59.94 but only 0.1 s at 120 fps; per-frame memory changes with dimensions/stride. Meter capacity is packet-count only. Introduce time and byte budgets with minimum slot counts, overflow-safe byte arithmetic, and declared format validation. Test multiple audio callback sizes/rates and padded video strides, asserting equivalent buffered duration and an absolute byte ceiling.

## SDK/native ownership boundaries

DeckLink callback obtains an IOSurface-backed SDK pixel buffer, forwards it synchronously and releases its local CVPixelBuffer reference (`DeckLinkBackend/UltracamBackend.mm:887-908`). Any downstream retain delays native reuse. Native audio copies have a 96,000-sample-frame per-packet validation bound (`:633`, `:678`); this is not an aggregate queue bound. Device reconfiguration counts SDK queued/gated frames (`:1057-1065`). The controller's unchecked source dispatch backlog is therefore a direct path to native pool pressure despite recording's separate raw-buffer caps.

`stop` invalidates generations and GPU/delivery paths reject stale work, but generation checks do not reclaim already queued closures immediately. Teardown tests must count live owners through the drain, not merely assert no stale UI publication. Bridge replacement calls prior.stop before starting the next session; ownership must remain valid across that lifecycle boundary.

## Suggested implementation order and acceptance evidence

First preserve typed owners end-to-end and add deterministic owner-release tests. Then add bounded source and source-only delivery admission with explicit refusal reasons/counters. Remove source ownership from reports that only need timing/format metadata. Keep recording's independent admission and Program cadence accounting intact. Follow with B1c format-aware duration/byte budgets across capture, recording, meters, normalization and camera queues.

For every overload test record admitted, rejected, delivered, generation-flushed and live-owner counts; verify conservation after draining. Run below-budget no-loss tests separately from intentional-overload refusal tests. Include stop/restart while each queue is blocked and ensure no old generation publishes, no owner is released before GPU completion, and no resource count grows with the number of refused frames. No implementation or tests were changed by this audit.

## A5 implementation checkpoint after the initial audit

The findings and inventory above record the pre-fix baseline. The following source review supersedes the corresponding rows; it does not retroactively describe them as safe. Core checkpoint supplied 2026-10-27; this audit agent did not run builds.

- **Findings 1 and 3 addressed:** `CaptureAdmissionBudget` admits before the controller frame dispatch, with defaults of 12 slots, 384 MiB padded storage, and 0.25 seconds of source duration, with a three-slot duration floor. Hard byte and slot limits always apply. A lease spans capture queue, GPU completion, ordered source-only offers and delivery. `coreRejectedFrames` separately counts admission refusals. Recording's callback intentionally precedes this processing budget, preserving its independent bounded admission. Downstream monitor slots, recording, output pools and CMIO have separate additive budgets; 384 MiB is not a process-wide memory cap.
- **Finding 2 addressed:** `CapturedPixelBuffer` attaches a deduplicated storage-owner collection to the CVPixelBuffer with nonpropagating attachment mode. Legacy raw CV consumers consequently keep the explicit owner alive. The owner contract prohibits retaining that same pixel buffer, avoiding a cycle. GPU passthrough copies propagating attachments plus explicitly named standard image metadata; it omits nonpropagating ownership attachments, so an independently owned output does not pin source SDK leases.
- **Finding 4 addressed for frame retention:** `DeliveryReport` now stores scalar `DeliveryMetadata`, not the owning `DeliveryItem`. The report dispatch remains queued metadata, but cannot retain source storage, admission leases, preview closures or monitor sinks. Work entering GPU-to-delivery is bounded by the shared lease budget. Source-only delivery rechecks generation and epoch before calling the sink.
- Typed media statistics are consumed synchronously without a PCM-owning capture-queue hop. Typed events can still enqueue metadata/reason strings without a count cap; this is not an unbounded frame/PCM retention path. Recording callback execution before processing admission is synchronous; recording's own pending-video/audio admission supplies its separate bound.
- Typed epoch revision checks retire queued frames after format/epoch transitions, and explicit paired-frame sequencing survives recorder refusal without assigning stale pairing to unpaired audio.

### Remaining scope

**B1c remains pending** for recording packet/frame caps, meter packet capacity, encoder and pool/cache byte/time sizing, and other count-based downstream budgets. The original timecode-FIFO growth suggestion is a targeted test hypothesis, not a reproduced bug or a new A5 blocker. A capture admission lease bounds queued/in-flight controller work; it does not prove every-frame delivery under arbitrary overload. Supported-load no-loss tests and intentional-overload refusal tests remain distinct acceptance evidence.
