# Ultracam and MonitorKit code audit

On November 18, 2026, GPT-6.2 Astra agents reviewed Ultracam's app, camera extension, capture and device APIs, Program output, recording, first-party vendor adapters, Rust auto-switcher, build tooling and test infrastructure. The MonitorKit review covered rendering, shaders, scopes, audio, core and UI in both local checkouts.

Ultracam started at `572ba68`, its embedded MonitorKit at `1e81a95`, and standalone MonitorKit at `5a07e6c`. The embedded package already contained local edits. Fixes were applied in the working trees against their respective versions.

## Ultracam repairs

| Area | Observed failure and repair |
| --- | --- |
| Recording and recovery | Finalization now requires a regular movie file. Recovery preserves a directory occupying the export path, continues scanning other folders after an unreadable entry, and protects a partial recording from late cancellation after handoff to recovery. |
| Audio and timecode | PCM conversion checks plane sizes, integer sign and bit alignment before copying. The sample description identifies 24 significant bits in a 32-bit word. Packet state advances only after validating its end timestamp. Generated timecode uses drop-frame numbering only at supported rates. |
| Capture lifecycle | A superseded start can no longer reopen sample admission. Failed teardown preserves newly installed recording callbacks. Session replacement drains the old session and releases its callbacks even when the replacement factory throws. |
| Virtual cameras | Registry updates roll back partial native registration and ignore delayed removal callbacks for superseded devices. Queue telemetry uses the admission lock and checks duration bounds. Device discovery tolerates unreadable unrelated devices, demand tracking survives renames, and negotiation checks both streams before changing either. |
| Program output | Unusable first frames no longer mark an input on air or shorten its startup deadline. Mapping an imported timeline resets the previous source origin. The renderer validates pixel-aspect metadata, retains chroma at odd v210 widths, resets cadence across source generations, and clears queue-stall state when a sink closes. |
| Auto-switching | The Rust director considers all observations at the same timestamp before cutting. Offline duration includes the last audio chunk. Re-selecting a recording folder preserves the current timeline file, and a new take starts with fresh time bounds. |
| Device integration | Capture-claim cleanup and DeckLink stop tolerate repeat calls. DeckLink validates timecode separators and signed labels. Sony discovery retains CDATA mixed with ordinary UTF-8 text. |
| App state and UI | Failed device enumeration preserves the last inventory. A late statistics poll cannot overwrite final recording telemetry. Migration honors an explicitly saved input choice. Settings reset waits for active recovery. UI fixes cover alert sound and observation, shortcut registration, camera removal and renaming, false-color source selection, and clean/frozen monitor indicators. |
| Builds and tests | The checked-in project builds without the optional Sony SDK. Canonical verification compares generated outputs in a temporary directory. CI initializes paths on the runner. Local staging protects existing apps and symbols on failure, dSYM archiving serializes concurrent writers, and the synthetic app self-test uses offline hardware and isolated preferences. |

## MonitorKit repairs

| Area | Observed failure and repair |
| --- | --- |
| Frame decoding and shaders | The raw decoder accepts a complete final row without trailing stride padding. Standalone MonitorKit supports repeated inclusion of the monitor shader in a host library. |
| Layout, LUTs and scopes | Cube LUT parsing consumes one line at a time and reports correct CRLF line numbers. A narrow picture fits inside a one-pixel viewport. Magnified guide grids visit visible columns instead of allocating offscreen segments across the entire image. Standalone scope sizing handles very large dimensions. |
| Rendering and meters | GPU failures during idle cleanup reach the host after the renderer releases its lock. Failure of an older submission leaves a newer draw usable. Meter ballistics recover after nonfinite timestamps, and custom PPM return times must produce measurable decay. Standalone also validates loudness input before allocating and handles refresh jitter. |
| Test reliability | Metal 4 submission helpers close abandoned indices so a thrown encoding operation cannot hang a later drain. Release-mode scope tests keep resources alive through completion and compare heap allocation with equivalent Metal dispatches. Five previously undiscovered clean-aperture cases are registered in standalone MonitorKit. |

## Verification

| Run | Result |
| --- | --- |
| Ultracam app XCTest executable | All 1,672 tests passed across 172 suites. Runtime discovery matched the registered tests, with zero skips. |
| Standalone MonitorKit, Release | All 1,110 distinct tests passed. The default run skipped 11 opt-in cases. Separate runs exercised those cases with window tests, benchmarks and Metal shader validation enabled. |
| Embedded MonitorKit | All 1,115 distinct tests passed across the default and opt-in runs. The 2560×1440 picture-pass benchmark measured 0.584 ms against its 0.55 ms budget on the first run and passed the project's permitted retry. |
| Rust auto-switcher and Python contracts | All 29 Rust tests and 180 Python contract tests passed. |
| App and monitor integration | All 38 integration checks passed. The optional-Sony unsigned arm64 Release built, passed bundle validation and passed all 39 real-app UI checks using offline hardware and isolated preferences. The first UI run used ordinary app preferences and permitted enumeration before the isolation fix. |
| Interrupted recording | Recovery produced playable movies for ProRes and HEVC after stopping writers at 4 and 14 seconds. Each original partial movie remained unchanged. |

The 216-format standby check retained its pixel assertions. Waiting for the actual output callback reduced the focused run from 243 seconds to 1.14 seconds on the audit host.

The main verification commands were `bash scripts/test.sh` in Ultracam and `swift test -c release` in standalone MonitorKit. The app integration and interrupted-writer checks use `bash scripts/monitor-app-integration.sh` and `bash scripts/recording-recovery-smoke.sh`. The app UI check used `SKIP_BUILD=1 bash scripts/app-self-test.sh` against the unsigned Release build with the optional Sony SDK enabled.

## Verification boundaries

The audit used synthetic capture, GPU readback, native adapter checks and a local unsigned macOS Release build. Physical camera hot-plug, live Sony and DeckLink operation, installed-extension client behavior and credentialed release signing require separate validation. Third-party SDK implementations were outside the review.
